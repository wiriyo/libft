## ไฟล์มี 3 ประเภท (แยกให้ออก แค่นี้ก็ไม่งง)

| ประเภท | ไฟล์ | ต้องทำอะไร | ส่งไหม |
|--------|------|-----------|--------|
| **1. ไฟล์งานจริง** | `ft_putchar_fd.c`, `ft_putstr_fd.c`, `ft_putendl_fd.c`, `ft_putnbr_fd.c` | ด้านบน = **คำอธิบาย (description)** / ด้านล่าง = ฟังก์ชัน + ช่อง `/* TODO */` → **พี่เติมตรง TODO** | ✅ ส่ง |
| **2. ไฟล์เดโม** | `demo_fd.c` | รันดูให้เห็นภาพ fd อย่างเดียว | ❌ ไม่ส่ง |
| **3. ไฟล์เทสต์** | `main.c` | รันตรวจว่าโค้ดพี่ถูกไหม (PASS/FAIL) | ❌ ไม่ส่ง |

## "ไฟล์ desc" = ประเภทที่ 1

คือไฟล์ `.c` ที่ชบาใส่ **comment คำอธิบาย** ไว้ข้างบน แล้วเว้นช่องว่างให้พี่เติมโค้ดข้างล่าง
— ไม่ใช่ไฟล์วิเศษอะไร แค่เรียกกันเล่นๆ ว่า "ไฟล์ที่มี description ให้อ่านแล้วเติม"

หน้าตาข้างในเป็นแบบนี้:

```c
/* =========================================
**  หน้าต่างคำอธิบาย (description) — อ่านอย่างเดียว
**  บอกว่าฟังก์ชันทำอะไร + เคสที่เทสต์จับ
** ========================================= */
#include <unistd.h>
#include "libft.h"

void	ft_putchar_fd(char c, int fd)
{
	/* TODO: เขียน c ลง fd (1 บรรทัด) */   <-- พี่เติมตรงนี้
	(void)c;   <-- บรรทัดกัน warning ตอนยังไม่เขียน ลบทิ้งได้
	(void)fd;
}
```

## ขั้นตอนตอนนี้ (ทำทีละตัว)

1. เปิด `ft_putchar_fd.c` → อ่านคำอธิบายบนสุด → เติม 1 บรรทัดใน TODO
2. รันเทสต์: `gcc -Wall -Wextra -Werror main.c ft_putchar_fd.c -o t1` — ถ้าติด undefined reference เพราะไฟล์อื่นยังว่าง ให้ใช้คำสั่งเต็ม:
   `gcc -Wall -Wextra -Werror main.c ft_putchar_fd.c ft_putstr_fd.c ft_putendl_fd.c ft_putnbr_fd.c -o test_putfd`
3. `./test_putfd` → ดู FAIL ค่อยๆ เปลี่ยนเป็น PASS

## 🧠 ภาพเดียวที่ต้องจำ

`write(fd, ...)` = **ส่งพัสดุไปบ้านเลขที่ fd**
- บ้านเลข **1** = จอ (ft_putchar เดิมฮาร์ดโค้ดเลขนี้)
- บ้านเลข **3** = ไฟล์ที่เพิ่ง open() (OS แจกเลขให้เอง)
- `_fd` = เปลี่ยนจาก "เลข 1 ตายตัว" → "เลขที่คนเรียกส่งมา"
